# 開始指示受理と配送世代を永続化する

Pionsは、ワーカーが受理した開始指示と、現在の配送世代および配送主体からなる開始配送権限を、オペレーションの非公開実行ディレクトリへ永続化する。開始指示はワーカープロトコルの現行スキーマで検証し、排他的作成、ファイル同期、ディレクトリ同期を終えた後にだけ受理済みとする。開始配送権限の更新も置換用ファイルへの書き込みと同期を経て確定する。読み取り不能、不正な内容、または永続化失敗を未受理へ変換しない。

ワーカープロトコルは、永続受理の通知である`begin_accepted`と、その通知を配送主体が永続化した後の`begin_ack`を別フレームにする。配送主体は受理事実の永続化後に`begin_acceptance_observed`を返し、ワーカーはそれを確認してから`begin_ack`を返す。同じ開始指示の再送でもこの交換を繰り返すが、プロンプトは再投入しない。競合、対象ワーカー不一致、期限切れ、旧配送世代、および受理状態不明は、認証済みの`begin_rejected`として返す。

外部の開始許可を使わないプロファイルでは開始指示に期限を持たせない。起動証跡ダイジェストには、タスクと実効設定から導出した自動開始スコープのダイジェストを使用し、外部の起動証跡を装わずに開始同一性を固定する。

配送主体の引き継ぎでは、ワーカーが世代更新と開始指示受理を直列化し、`generation_updated`へ更新時点の受理状態を含める。同じ配送主体から同じ配送世代の更新を再受信した場合は、永続化済みの開始配送権限と照合して同じ確認応答を返す。世代番号の保存だけを旧配送主体の遮断証明とは扱わない。ランタイム成果物ストアの排他所有によって旧ランタイムが書き込み主体ではないことを確認し、開始配送権限の失効をイベントへ記録したうえで、ワーカーの世代更新応答が揃うまで引き継ぎを完了しない。

ランタイム起動時には、送信処理へ進入済みで停止未確認のオペレーションをイベントストアから列挙する。ワーカー拡張は接続喪失後も同じプロセス実体識別子と永続受理ストアを保って再接続する。後継ランタイムは認証済み接続と保存済みワーカー実体を照合し、世代更新応答が未受理の場合だけ期限、キャンセル、開始許可主体、および資源証明を再検査して再配送する。受理済みは既存の受理事実として回収し、不明は再配送せず停止確認へ進める。

この決定は、認証済みローカルワーカープロトコルを定めたADR-0002と、外部着手許可と資源権限を分離したADR-0006を具体化する。
