# 信頼済み正式レビューブートストラップで実装識別情報を検査する

正式レビュー統合の公開入口は、変更不能なモジュール識別子と契約版を公開する。利用者所有の信頼済みブートストラップは、期待する契約版、利用先リポジトリの正規ルート、不透明なリポジトリ識別子、その識別情報を検証する`verifyIdentity`、および承認済み資源アダプター識別情報を明示して統合を構成する。リポジトリ検証主体は、正規リモートや署名済み管理情報など、パス以外の信頼済み根拠を利用者の運用に応じて検査する。Pionsは構成時に実際の正規ルート、リポジトリ検証結果、契約版を照合し、資源アダプターについて識別子、版、登録成果物のダイジェスト、および用途を、ブートストラップの承認一覧と主体登録の両方から照合する。不一致や検査不能は安全側で拒否する。

資源アダプターの登録成果物は、実装を表す正確なバイト列として信頼済みホストが渡す。Pionsはブートストラップ構成時と資源アダプターの主体登録時にそのダイジェストと承認一覧を検証するが、渡された実行関数と登録成果物の対応を推測しない。この関係は信頼済みブートストラップとアダプター登録主体の責任であり、パス一致や利用先リポジトリの設定から推論しない。通常の`.pions.json`は従来どおり読み取り委譲のモデルと思考量だけを扱い、アダプター読込先、資格情報、プロファイル権限、正式レビューの有効化範囲を受け取らない。

非本番構成では、明示的に非本番用途とされたアダプターと内部テスト差し替えを用いて公開統合境界を検証できる。本番構成では非本番アダプターと内部テスト差し替えを拒否し、段階導入承認が別途成立するまで正式レビュー設定自体を拒否する。単体・統合テストの合格やレビュー入力準備完了を、本番ホストにおける継続的なアクセス隔離、秘密配送、停止・遮断、または後始末の証拠として扱わない。

本決定はADR-0019の公開操作を増やさない。公開入口から得られる操作はレビュー対象登録と設定済みPi拡張導入の2つのままとし、モジュール識別情報と信頼済みブートストラップ構成をその入口の契約へ追加する。
