# 呼び出し元の終了後もバックグラウンドのオペレーションを継続する

Pionsに、既存の待機する委譲とは別に、オペレーション識別子を返して待機を終えるバックグラウンド委譲を追加する。バックグラウンド委譲の呼び出し元Piセッションが終了、切り替え、または再読み込みされても、それだけを理由にワーカーをキャンセルしない。結果受理、停止確認、表示終了処理の要件は待機する委譲と同じであり、識別子の返却を結果受理や終端完了と取り違えない。呼び出し元は既存の`pions_operation`と`pions_result`で状態と結果を取得し、停止したい場合だけオペレーション識別子による明示的なキャンセルを要求する。暗黙の自動再試行、完了通知、チェーンは追加しない。この決定はADR-0025の同期委譲だけを提供し、呼び出し元の終了時にすべての委譲をキャンセルする方針をバックグラウンド委譲に限って変更する。

現在の`Runtime`は呼び出し元Piプロセス内にあり、セッション終了時に稼働中のオペレーションをキャンセルし、`close()`も稼働中の処理を待つ。単にツールの待機を省く実装では、呼び出し元が閉じた後にワーカープロトコルを受信して結果受理と停止確認を行えない。このためバックグラウンド委譲の実行と復旧は、呼び出し元Piプロセスから独立した所有者が担う。起動要求は所有者が永続化されたオペレーションの識別子を返した後にだけ成功とし、呼び出し元が要求の応答を失った場合も同じ要求で重複実行しない。永続記録への更新はオペレーションごとに一つの所有者に限り、呼び出し元Piの復旧処理と独立した所有者が同時に書き込まないようにする。所有者が不意に停止した場合は、次にPionsが起動したときに所有権の失効を確認したうえで、既存の認証済みワーカープロトコルと永続記録から復旧する。所有権や開始、停止を証明できなければ状態不明のまま残し、推測で同じ作業を再実行しない。所有者不在を終端完了やキャンセルとみなさず、その間に結果受理まで完了できるとは約束しない。

明示的なキャンセルは識別子を知るだけでは認めず、現在の信頼済みリポジトリの権限を検査する。キャンセル要求への応答と、ワーカー停止確認後のキャンセル成立を区別する。独立した所有者は、同じパッケージに含まれるNodeプロセスとしてオペレーションごとに起動し、所有期間をカーネルがプロセス終了時に解放する抽象Unixソケットで区別する。所有者へのキャンセル要求は、信頼済みリポジトリの私有保存領域に置いた鍵で認証する。ワーカー設定と要求を私有ファイルへ保存するが、環境変数と認証情報は保存せず、起動する子プロセスの環境から受け取る。既存の待機する委譲では、ツール中断およびPiセッション終了時のキャンセル方針を維持する。バックグラウンド委譲が共有作業ディレクトリへ直接書き込むことも変わらないため、呼び出し元は競合する書き込みを同時に依頼しない。
