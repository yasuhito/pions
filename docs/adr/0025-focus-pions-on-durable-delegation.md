# Pionsを永続的な委譲へ絞る

Pionsの製品境界を、親エージェントによる汎用サブエージェントの起動、結果の永続化と返却、およびオペレーション識別子による結果と状態の再取得へ絞る。正式レビュー、資源証明、着手許可、外部レビュー割り当て、レビュー対象登録、改訂系列、および本番段階導入はこの境界から外し、無効な機能として維持せずコード、公開契約、テスト、文書から削除する。各オペレーションが保存・返却する結果は、サブエージェントの最終回答であるUTF-8テキスト1件だけとする。添付ファイル、バイナリ成果物、および作業成果物の登録は扱わず、ファイル変更は共有する作業ディレクトリに残す。受理した結果は自動削除せず、利用者がPionsの保存領域を明示的に削除するまで保持する。Herdrは必須とし、1つのオペレーションにつき1つのワーカーワークスペースを現在の作業ペインとは別に作成して、利用者がHerdrの左側のワークスペース一覧から必要なときだけ表示できるようにする。ワーカーワークスペースの表示名は作業内容を含めず、`Pions <短いOperation識別子>`とする。結果受理、ワーカー停止、および所有ワークスペースの同一性を確認できた正常終了時だけワークスペースを自動で閉じ、失敗または状態不明の場合は調査用に残す。親が委譲をキャンセルした場合はワーカーへ停止を要求し、停止を確認できればキャンセル済みとしてワークスペースを閉じ、確認できなければ状態不明としてワークスペースを残す。Pions専用の手動終了機能は追加せず、利用者が明示的に閉じる場合はHerdrの既存機能を使う。委譲は親から汎用サブエージェントへの一段だけとし、サブエージェントによる追加の委譲と子孫オペレーション管理は範囲外とする。`pions_delegate`は結果受理まで待つ同期方式だけを提供し、バックグラウンド実行と完了通知は範囲外とする。失敗した委譲は自動で再実行せず、親が必要性と作業ツリーの状態を確認してから新しいオペレーションとして明示的に開始する。親セッションやRuntimeが実行途中で終了しても、同じオペレーションの状態確認と結果受理を安全に再開する。再実行の安全性を確認できなければ状態不明として残し、同じ作業を推測で再実行しない。汎用サブエージェントには`read`、`write`、`edit`、`bash`、`grep`、`find`、`ls`を提供するが、`pions_delegate`は提供しない。親と同じ作業ディレクトリを使い、Pionsはworktree、ブランチ、変更の受け渡しを管理しない。競合する書き込み委譲を並列実行しない責任は親に置く。`pions_delegate`の入力は`task`だけに保ち、サブエージェントのモデルと思考量は信頼済みリポジトリの`.pions.json`直下に`model`と`thinkingLevel`として設定する。正式レビュー由来の`review`階層は削除し、旧形式との互換処理は設けない。利用者向けの公開契約はPi拡張が提供する`pions_delegate`、`pions_result`、`pions_operation`の3ツールだけとし、汎用のJavaScriptライブラリAPIは公開しない。Pionsはモデルプロバイダーを同梱または自動読込せず、`.pions.json`で指定したプロバイダーの導入と認証をPi環境へ委ねる。利用不能な場合はワーカーを開始せず設定エラーを返す。最小機能の完成には、利用先が`@yasuhito/pions`の固定バージョンを通常のnpm依存として導入できる配布を含め、最初の公開版を`0.1.0`とし、実際にパッケージを導入した利用先でPiとHerdrを起動し、委譲、結果受理、再取得、およびワークスペース終了を通す自動E2Eテストの合格を公開条件とする。最小の委譲経路はすでに動作しており、その信頼性と配布を完成させる方が、利用予定のない機能の責任と複雑さを維持するよりPionsの目的に直接つながるためである。
