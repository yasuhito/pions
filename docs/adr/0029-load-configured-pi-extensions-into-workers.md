# 設定したPi拡張をワーカーへ読み込む

ワーカーは引き続き`--no-extensions`で起動するが、Pions内部拡張に加えて、信頼済みリポジトリの`.pions.json`直下の`extensions`に列挙したPiパッケージと、Herdrの状態連携だけを個別の`--extension`で読み込む。`extensions`にはPiの設定と同じパッケージ指定(`npm:pi-web-access`や`git:https://github.com/elidickinson/pi-claude-bridge`など)を書き、Pionsは委譲元のPiがすでに導入し有効にしているパッケージの拡張ファイルをPi自身のパッケージ解決で求める。導入されていない、または無効なパッケージはダウンロードせず、ワーカーを開始する前に設定エラーとする。Pions自身のパッケージは読み込まない。Herdrの状態連携は、Piの設定ディレクトリ(`PI_CODING_AGENT_DIR`、未指定なら`~/.pi/agent`)の`extensions/herdr-agent-state.ts`があれば設定なしで読み込み、なければ読み込まずに開始する。表示のための連携であり、委譲の成否を左右しないためである。読み込んだ拡張のパッケージ指定とファイルは実効設定としてオペレーションに永続化する。

利用者の環境にある拡張をすべて読み込むのではなく列挙したものだけに限るのは、人の操作を前提とする拡張が無人のワーカーで動くことを避け、ワーカーで何が動くかを設定から判断できるようにするためである。一方、読み込まないままでは、Pi拡張が提供するモデルプロバイダー(`claude-bridge`など)やツールをワーカーで使えなかった。

ワーカーのPi組み込みツールは`read`、`write`、`edit`、`bash`、`grep`、`find`、`ls`のままとし、読み込んだ拡張が登録したツールもすべて使えるようにする。ワーカーが報告する有効ツールは、実効ツールをすべて含み、それ以外のPi組み込みツールと`pions_delegate`を含まない場合だけ受け付ける。Piはどの拡張がプロバイダーを登録したかを公開しないため、Pi拡張由来のプロバイダーを使うのに`extensions`が空の場合だけ、開始前に`extensions`への追記を求める設定エラーを返す。それ以外の書き誤りは、ワーカー識別期限による起動失敗か、観測したモデルの不一致として失敗する。

ワーカーが起動した子孫プロセスまで停止したことを、成功とキャンセルの停止確認に含める。成功時はワーカーが終了する前、結果受理の確認応答を送る直前に子孫を捕捉し、ワーカー終了後に子孫も停止したことを確認できなければ状態不明とする。キャンセル時は子孫も終了させ、停止を確認できなければ状態不明とする。捕捉はワーカーのプロセス木を辿るため、捕捉より前にワーカーの親子関係から外れたプロセスは対象にならない。失敗時はADR-0026どおり調査のためにワーカーを止めない。

エージェントが失敗した場合、モデルプロバイダーが返したエラー文を正規表現などで分類せず、UTF-8で4096バイトを上限にワーカー実行証拠としてそのまま永続化し、呼び出し元へのエラーにも添える。失敗理由は`agent_failed`だけとし、エラー文の意味の判断は呼び出し元に委ねる。エラー文の書き方はプロバイダーごとに異なり、分類はその変化に追従できないためである。

この決定は、ワーカーが拡張を読み込まないとしたADR-0005とADR-0025の該当部分を置き換える。
