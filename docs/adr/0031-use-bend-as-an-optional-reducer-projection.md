# Bend をオペレーション状態遷移の検証用投影に限定する

ランタイムと永続化の正本は `src/internal/event-store/reducer.ts` の TypeScript 実装とする。Bend 2 の `verification/bend/model.bend` は、状態、結果受理、停止確認、連番、および一部のイベントだけを扱う独立した投影である。`LAWS.bend` の履歴全体に関する法則を `PROOF.bend --safe` で検査し、`npm run verify:bend` で実際の TypeScript 遷移と固定乱数による履歴の各段階を比較する。通常のビルド・実行には Bend を必要としない。

この投影は全イベント、証跡、認証、保存形式、拒否理由、表示終了処理の前提条件を網羅しない。開始確認応答は事前のプロトコル検証済みという抽象イベントであり、差分テストの乱数対象には含めない。配送主体の同一性や引き継ぎの再開条件も抽象化する。差分テストは固定乱数による有限個の履歴だけを調べ、TypeScript の正しさを証明しない。終端状態には状態不明も含まれ、終端後の表示終了処理は状態を変えずに受け付ける場合があるため、「終端後はすべてのイベントを拒否する」という法則は採用しない。

Bend の通常の検査と `--safe` は異なる。任意の検証コマンド `npm run verify:bend` は Lean 4.34.0 を要し、後者も検査する。失効済み世代に関する法則は「失効後に旧世代の確認を新たに受け付けない」であり、確認後にその世代が失効することは許す。モデルの適用範囲を拡大するときは、実際の reducer と照合するテストおよび法則を一緒に更新する。
