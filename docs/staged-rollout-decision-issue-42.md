# Issue #42 段階導入判定記録

記録対象は、正式レビュー、書き込み、改訂・再試行の候補用途である。本記録は実装と統合検証の結果を示すものであり、本番プロファイルの登録、有効化、または有効化承認ではない。

## 判定

| 候補用途     | 検証結果                                         | 本番有効化                       |
| ------------ | ------------------------------------------------ | -------------------------------- |
| 読み取り     | 既存の既定動作を維持                             | 既存の`pions_delegate`だけを継続 |
| 正式レビュー | 候補設定と開始境界の保証を検証                   | 無効。別途承認が必要             |
| 書き込み     | 候補設定の必須保証を検証                         | 無効。別途承認が必要             |
| 改訂・再試行 | 予約、再試行安全証明、表示終了処理との分離を検証 | 無効。別途承認が必要             |

正式レビュー、書き込み、改訂・再試行の本番プロファイルは登録していない。Pi拡張内の`review`という設定キーは従来どおり`intendedUse: "reader"`であり、正式レビュー候補ではない。

## 検証した保証

### 共通の設定境界

- すべてのワーカープロファイルは候補用途を明示する。
- 候補用途の必要条件が不足する場合は、ワーカーとペインを作成する前に設定を拒否する。直接委譲ではオペレーション作成前に検査し、改訂・再試行予約では予約済みの実行タスクをオペレーションへ具体化する前に検査する。
- 不正な資源証明設定を`disabled`へ変更して処理を続けるフォールバックを廃止した。
- #34で確立したモデル、思考量、ツール、作業ディレクトリの要求・実効・観測設定照合を全テストの一部として再実行する。

### 正式レビュー候補

- `startAuthorization.policy`が`required`でなければ拒否する。
- 固定レビュー対象の検証が`required`でなければ拒否する。
- 許可要求の公開前にレビュー対象と依存閉包を保持して完全性を検証できなければ開始しない。
- 許可後、`begin`直前の取得と完全性再検証に失敗した場合は開始配送権限を取得せず、着手ゲートを無効化する。

### 書き込み候補

- 外部着手許可、資源証明、書き込みを宣言する権限目録、および1件以上の必須作業成果物要件を要求する。
- プロファイルのツールと権限目録が矛盾する場合、および資源証明設定が不完全な場合は拒否する。
- Result本文または必須作業成果物の部分保存では結果受理を公開しない。

### 改訂・再試行候補

- ワーカープロファイルには書き込み候補と同じ静的保証を要求する。
- 状態不明、ワーカー停止未確認、または資源解放未確認では、再試行安全証明を永続化する前にRetryを予約しない。
- 所有ペインの表示終了処理が完了済みでも、旧ワーカー、子プロセス、外部ジョブの停止またはアクセス遮断、競合不在、資源引き渡しの証明として扱わない。
- 再試行安全証明の保存失敗、対象不一致、または影響資源の不一致ではRetryを予約しない。
- 起動時には開始配送、改訂予約、および表示終了処理を独立に復旧し、表示終了処理証跡を再試行安全証明へ変換しない。

## 試験証拠

`npm run check`で型検査、1テスト1アサーション検査、および全テストを実行する。主な直接試験は次のとおりである。

- `test/worker-configuration.test.ts`: 候補用途ごとの必須設定、既存の思考量照合
- `test/runtime.test.ts`: 不完全な候補設定の非フォールバック拒否、作業成果物能力、表示終了処理復旧
- `test/start-authorization.test.ts`: 許可要求前の固定レビュー対象検証・保持、`begin`直前の再検証、期限と復旧時計
- `test/worker-protocol.test.ts`: 開始指示受理、配送世代、旧配送主体の遮断
- `test/revision-series.test.ts`: 状態不明と停止未確認時のRetry拒否、表示終了処理完了との分離、再試行安全証明の先行永続化
- `test/result-acceptance.test.ts`: Resultと作業成果物の一体受理、部分保存時の非公開
- `test/artifact-store.test.ts`: 保持参照とガベージコレクションの中断・再開、未処理、処理不能、検査不能、削除完了の区別

## 残る未達条件

本番有効化までに、候補用途ごとに次を別Issueと承認で確定する必要がある。

- 信頼済みコーディネーター、資源証明発行元、および資源アダプターの本番登録
- 正規ランチャーが発行する書き込みワークスペース証明と、実環境での観測・強制方法
- 外部ジョブと子プロセスの停止またはアクセス遮断を証明する運用
- 本番用の権限目録、作業成果物形式、保持期間、資源後始末方針
- 対象環境での決定的な障害試験と運用責任者による段階導入承認

これらが満たされるまで、正式レビュー、書き込み、改訂・再試行の候補用途は本番では無効とする。
