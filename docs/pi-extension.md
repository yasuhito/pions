# Pi拡張から作業を委譲する

信頼済みのPionsプロジェクトでは、プロジェクトローカルのPi拡張が`pions_delegate`ツールを登録する。利用前に`npm run build`を実行し、可視ワーカー用の内部拡張を生成しておく。特にワーカープロトコル版の変更後にビルドしないと、ホストと内部拡張の版がずれて`Worker configuration version does not match`になるため、同じコマンドで`dist`を更新してから再実行する。

`pions_delegate`は、独立したコンテキストへ渡す自己完結した`task`だけを受け取る。モデル、思考レベル、ツール、作業ディレクトリ、状態保存先はツール入力では変更できない。1回の呼び出しは1つのルート`Operation`に対応し、複数の独立した作業はPiの並列ツール実行によって構成する。

初期のワーカーはHerdrの兄弟ペインで、Pi公式の`regular` TUIを持つ一時セッションとして動く。利用可能な領域が横長なら右、縦長なら下へ、フォーカスを移さずペインを作成する。委譲元セッションのモデルと思考レベルを継承し、`read`、`grep`、`find`、`ls`、`bash`だけを利用する。ワーカーには`bash`を読み取り目的だけに使うよう指示するが、これは技術的な読み取り専用隔離でもセキュリティサンドボックスでもない。ワーカーは信頼済みプロジェクトの`AGENTS.md`、Pions内部拡張、およびPionsが監査して固定した選択モデル用プロバイダー拡張だけを読み込む。`--no-extensions`を維持するため、許可していないグローバル拡張やプロジェクト拡張、通常のスキル、プロンプトテンプレート、追加テーマは探索しない。TUIは観測専用であり、端末からの入力はすべて破棄する。

## レビュー用モデルの設定

リポジトリルートの`.pions.json`で、レビュー用のモデルと思考レベルを上書きできる。

```json
{
  "review": {
    "model": {
      "provider": "claude-bridge",
      "id": "claude-opus-5"
    },
    "thinkingLevel": "high"
  }
}
```

`model`または`thinkingLevel`を省略すると、その値だけを委譲元セッションから継承する。`thinkingLevel`には`off`、`minimal`、`low`、`medium`、`high`、`xhigh`、`max`のいずれかを指定する。モデルはプロバイダーとモデル識別子の正確な組で指定する。

設定には認証情報を記載しない。PionsはPiのモデルレジストリーと既存の認証を使用する。不正なJSON、未知のキー、不正な値は委譲を開始せずに拒否する。指定モデルがモデルレジストリーにない場合、認証されていない場合、またはワーカーで別のモデルが選択された場合も、委譲元モデルへ切り替えず型付き失敗を返す。

### Claude Pro/Maxの利用

依存関係の`pi-claude-bridge`は`0.7.0`へ固定されている。導入時は次を実行し、委譲元Piを再起動する。

```bash
npm install
npm run build
claude
```

最後のコマンドでは、利用者自身のClaude Pro/MaxアカウントでClaude Codeへログインして終了する。既定では`~/.claude`を使い、分離した保存先を使う場合は委譲元Piを起動する前に`CLAUDE_CONFIG_DIR`を指定する。OAuthトークンや資格情報を`.pions.json`、コマンド引数、タスク本文へ書かない。

Pionsのプロジェクト拡張は委譲元へ固定版プロバイダーを登録し、Claudeワーカーには同じパッケージの実エントリーをPions内部拡張と並べて渡す。起動直前にパッケージ名、版、エントリーの存在、および監査済みソース一式のダイジェストを検査するため、版または内容が異なる場合はオペレーションを作らず失敗する。Claude Code未ログインは`model_auth_unavailable`、モデル利用不可は`model_not_found`、プラン不適合は`unsupported_capability`として分類し、Codexなどへフォールバックしない。

`~/.pi/agent/claude-bridge.json`または`.pi/claude-bridge.json`は必要な場合だけ使う。`provider.plan`には実契約に応じて`pro`または`max`を指定でき、`pathToClaudeCodeExecutable`で未改変のClaude Code実行ファイルを指定できる。一方、Pionsワーカーは次の安全側の方針を必須とし、弱める設定を起動前に拒否する。

```json
{
  "askClaude": { "enabled": false },
  "provider": {
    "strictMcpConfig": true,
    "autoMemoryEnabled": false,
    "longContextExtraUsage": false
  }
}
```

`AskClaude`とClaude Code内蔵ツールは使わず、ワーカーPiで選択された読み取り中心ツールだけをMCP経由で橋渡しする。デバッグログにはプロバイダー由来の情報が含まれ得るため、`CLAUDE_BRIDGE_DEBUG`は通常運用で有効にしない。

作業内容とオペレーション権限は所有者だけが読み書きできるファイルで渡す。プロセス引数、オペレーションイベント、ログ、Herdrメタデータには本文を含めない。内部拡張が認証済みの`begin`を受信した後にだけ、作業内容をTUIの通常のユーザーメッセージとして投入する。状態は`XDG_STATE_HOME`が絶対パスならその配下、未指定または相対パスなら`~/.local/state`配下へ保存する。さらに、正規化したリポジトリルートのダイジェストでリポジトリごとに分離する。

Herdr環境がない場合でもツールの登録は維持される。実行すると`HerdrPreconditionError`になり、画面を持たない実行へは切り替えない。ワーカー失敗も自動再試行せず、`Operation`識別子と型付きの理由を含む失敗として呼び出し元へ返す。成功時は永続化済み`Result`の本文を返し、切り詰めの有無にかかわらず本文末尾へ`Operation`識別子を付ける。詳細としても`Operation`識別子、バイト数、ダイジェスト、および終了処理診断の一覧を返す。診断がない場合も一覧は空であり、診断を`Result`本文へ混入させたり成功を失敗へ変更したりしない。結果受理の確認後にPiへ正常終了を要求し、開始トークンを含むプロセス識別情報で停止を確認する。Claudeワーカーのキャンセルでは、要求前にAgent SDK配下の子孫プロセスも開始トークン付きで捕捉し、Piと捕捉したClaude Codeプロセスの両方が停止した場合だけ停止証拠を成立させる。停止を証明できた成功オペレーションでは、永続記録されたPions所有のペインだけを自動で閉じる。ペイン閉鎖に失敗しても受理済みの結果と終端完了は維持し、表示後処理の失敗をオペレーションへ記録する。ペイン閉鎖と診断保存がともに失敗した場合も、完了応答に残る両方の終了処理診断をツールの詳細へ伝播する。結果受理、Pi終了、または停止を証明できない場合と、失敗またはキャンセルの場合は、ペインを調査用に保持する。

親のモデルコンテキストへ返す本文は、切り詰め通知を含めてPi標準の2000行または50KB以内に収める。切り詰めた場合も完全な`Result`は永続記録に残り、通知と詳細の`Operation`識別子から参照できる。

`pions_result`は、現在の信頼済みリポジトリに保存された`Operation`の結果を再取得する。入力は`operationId`と、続きがある場合に直前の応答から受け取った`cursor`だけである。成果物の保存場所や分割サイズは指定できない。各断片は成果物全体の完全性検証後に返され、応答には次の断片用カーソルまたは完了表示が含まれる。Piセッションを再起動した後も、同じリポジトリの状態保存先を開いて取得できる。別リポジトリの識別子に対しては、保存場所、存在、削除、破損などを識別できる情報を返さない。

## セッションとオペレーションの寿命

ツール実行がPiから中断された場合、`pions_delegate`は対応する稼働中`Operation`へ部分木キャンセルを1回要求し、Pionsが停止の証拠を分類するまで待つ。結果待ちをローカルで中断したことや、プロセスへシグナルを送れたことだけではキャンセル成功としない。停止を証明できない場合は`OperationUnknownError`、証明できた場合は`OperationCancelledError`としてオペレーション識別子とともに呼び出し元へ返す。

Piセッションの終了、新規作成や再開による切り替え、フォーク、拡張の再読み込みでは、拡張の終了処理が追跡中のすべての稼働中`Operation`へ部分木キャンセルを要求し、すべての分類が終わるまで待つ。中断経路同士が重なっても、同じ`Operation`への要求は1回にまとめる。キャンセル済み、停止を証明できない状態、キャンセル処理の失敗のいずれでも、Pions所有のHerdrペインと永続的な`Operation`記録は削除せず、調査に利用できる状態で保持する。

## モデルによる委譲の選択

ツールの説明と利用指針は、サブエージェントへの委譲や独立したコンテキストでの調査に`pions_delegate`を使い、独立した複数の作業をPiの並列ツール実行で構成するようモデルへ伝える。特定のスキル名や本文を検出する処理は持たない。この説明によってモデルがツールを選ぶことは形式的な保証ではなく、実モデルによる確率的な振る舞いである。Issue #23で実施したモデルによる委譲選択の受け入れ確認は[Issue #23手動スモークテスト](manual-smoke-test-issue-23.md)、Pi CLI可視ワーカーの表示とライフサイクルの受け入れ確認は[Issue #29手動スモークテスト](manual-smoke-test-issue-29.md)に記録する。
