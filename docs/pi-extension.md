# Pi拡張から作業を委譲する

信頼済みのPionsプロジェクトでは、プロジェクトローカルのPi拡張が`pions_delegate`、`pions_result`、`pions_operation`の3つのツールだけを登録する。正式レビュー用のツールは登録しない。利用前に`npm run build`を実行し、可視ワーカー用の内部拡張を生成しておく。特にワーカープロトコル版の変更後にビルドしないと、ホストと内部拡張の版がずれて`Worker configuration version does not match`になるため、同じコマンドで`dist`を更新してから再実行する。

`pions_delegate`は、独立したコンテキストへ渡す自己完結した`task`だけを受け取る。モデル、思考レベル、ツール、作業ディレクトリ、状態保存先はツール入力では変更できない。1回の呼び出しは1つのルート`Operation`に対応し、複数の独立した作業はPiの並列ツール実行によって構成する。

ワーカーはHerdrの兄弟ペインで、Pi公式の`regular` TUIを持つ一時セッションとして動く汎用サブエージェントである。利用可能な領域が横長なら右、縦長なら下へ、フォーカスを移さずペインを作成する。委譲元セッションのモデルと思考レベルを継承し、`read`、`write`、`edit`、`bash`、`grep`、`find`、`ls`を利用する。`pions_delegate`はワーカーへ提供しないため、委譲は親から一段だけである。ワーカーは親と同じ作業ディレクトリで動き、そこへ直接変更を加える。Pionsはworktreeやブランチを作らず、変更の受け渡しも管理しない。書き込みが競合する委譲を並列実行しない責任は親に置く。失敗した委譲は自動で再実行せず、必要なら親が新しいオペレーションとして明示的に開始する。ワーカーは信頼済みプロジェクトの`AGENTS.md`とPions内部拡張だけを読み込む。`--no-extensions`を維持するため、グローバル拡張やプロジェクト拡張、通常のスキル、プロンプトテンプレート、追加テーマは探索しない。TUIは観測専用であり、端末からの入力はすべて破棄する。

## ワーカーモデルの設定

リポジトリルートの`.pions.json`で、ワーカーのモデルと思考レベルを固定できる。直下の`model`と`thinkingLevel`だけを受け付ける。

```json
{
  "model": {
    "provider": "anthropic",
    "id": "claude-opus-5"
  },
  "thinkingLevel": "high"
}
```

`model`または`thinkingLevel`を省略すると、その値だけを委譲元セッションから継承する。`thinkingLevel`には`off`、`minimal`、`low`、`medium`、`high`、`xhigh`、`max`のいずれかを指定する。モデルはプロバイダーとモデル識別子の正確な組で指定する。以前の`review`階層は未知のキーとして拒否し、互換処理は設けない。

設定には認証情報を記載しない。PionsはPiのモデルレジストリーと既存の認証を使用する。不正なJSON、未知のキー、不正な値は委譲を開始せずに拒否する。指定モデルがモデルレジストリーにない場合、認証されていない場合、またはワーカーで別のモデルが選択された場合も、委譲元モデルへ切り替えず型付き失敗を返す。

Pionsはモデルプロバイダーを同梱せず、委譲元やワーカーへ自動で読み込まない。プロバイダーの導入と認証はPi環境の責任である。ワーカーは拡張を探索しないため、委譲元セッションでPi拡張が登録したプロバイダー(Pi組み込みではないプロバイダー)はワーカーで使えない。そのプロバイダーが設定または継承された場合は、ワーカーを開始する前に`unsupported_capability`の設定エラーを返し、別のプロバイダーへ暗黙に切り替えない。

作業内容とオペレーション権限は所有者だけが読み書きできるファイルで渡す。プロセス引数、オペレーションイベント、ログ、Herdrメタデータには本文を含めない。内部拡張が認証済みの`begin`を受信した後にだけ、作業内容をTUIの通常のユーザーメッセージとして投入する。状態は`XDG_STATE_HOME`が絶対パスならその配下、未指定または相対パスなら`~/.local/state`配下へ保存する。さらに、正規化したリポジトリルートのダイジェストでリポジトリごとに分離する。

Herdr環境がない場合でもツールの登録は維持される。実行すると`HerdrPreconditionError`になり、画面を持たない実行へは切り替えない。ワーカー失敗も自動再試行せず、`Operation`識別子と型付きの理由を含む失敗として呼び出し元へ返す。成功時は永続化済み`Result`の本文を返し、切り詰めの有無にかかわらず本文末尾へ`Operation`識別子を付ける。詳細としても`Operation`識別子、バイト数、ダイジェスト、および終了処理診断の一覧を返す。診断がない場合も一覧は空であり、診断を`Result`本文へ混入させたり成功を失敗へ変更したりしない。結果受理の確認後にPiへ正常終了を要求し、開始トークンを含むプロセス識別情報で停止を確認する。停止を証明できた成功オペレーションでは、永続記録されたPions所有のペインだけを自動で閉じる。ペイン閉鎖に失敗しても受理済みの結果と終端完了は維持し、表示後処理の失敗をオペレーションへ記録する。ペイン閉鎖と診断保存がともに失敗した場合も、完了応答に残る両方の終了処理診断をツールの詳細へ伝播する。結果受理、Pi終了、または停止を証明できない場合と、失敗またはキャンセルの場合は、ペインを調査用に保持する。

親のモデルコンテキストへ返す本文は、切り詰め通知を含めてPi標準の2000行または50KB以内に収める。切り詰めた場合も完全な`Result`は永続記録に残り、通知と詳細の`Operation`識別子から参照できる。

`pions_result`は、現在の信頼済みリポジトリに保存された`Operation`の結果を再取得する。入力は`operationId`と、続きがある場合に直前の応答から受け取った`cursor`だけである。成果物の保存場所や分割サイズは指定できない。各断片は成果物全体の完全性検証後に返され、結果受理識別子、受理した原文バイト列のSHA-256ダイジェスト、および次の断片用カーソルまたは完了表示を含む。結果受理識別子は`pions_operation`が返す結果受理と同じ値であり、外部の正規化済み文書のダイジェストとは区別する。Piセッションを再起動した後も、同じリポジトリの状態保存先を開いて取得できる。別リポジトリの識別子に対しては、保存場所、存在、削除、破損などを識別できる情報を返さない。

## 正式レビューの依頼と状態確認

Pi拡張は正式レビュー用の`pions_review`と`pions_review_decision`を登録しない。これらは後続の削除まで残る`pions/formal-review`統合が正式レビュー設定を明示的に渡した場合にだけ登録され、通常の利用者経路からは到達できない。以下はその統合の説明である。

信頼済みホストは、グローバルに導入したパッケージの`pions/formal-review`から`createFormalReviewIntegration`を読み込む。この公開モジュールが返す操作は、固定ルート成果物を登録する`registerReviewSubject`と、設定済みPi拡張を導入する`installPiExtension`だけである。Runtime、Artifact Store、リポジトリごとの状態パス、資格情報、復旧処理、およびテスト専用差し替えは公開しない。

利用者所有の信頼済みブートストラップは、公開されたモジュール契約版、利用先の正規ルート、リポジトリ識別子とパス以外の信頼済み根拠を確認する`verifyIdentity`、および承認済み資源アダプターの識別子、版、登録成果物ダイジェスト、用途を固定して渡す。Pionsは実際の正規ルート、モジュール契約版、登録されたアダプター識別情報を照合し、不一致を安全側で拒否する。アダプターのパスは公開構成に含めず、パス一致を実装の許可として扱わない。通常の`.pions.json`からアダプター、資格情報、プロファイル権限、有効化範囲を選択できない。本番構成は非本番アダプター、内部テスト差し替え、および正式レビュー設定を拒否し、[Issue #67の段階導入判定記録](staged-rollout-decision-issue-67.md)に残した未達条件が別途承認されるまで正式レビューを無効のままにする。

登録操作は、依存要件と依存ファイルが同じ閉じた集合であること、パスが正規化された相対パスであること、および各バイト数とダイジェストが一致することを検査する。検査後は依存成果物を先に登録し、それらを参照する変更前のルートバイト列を後から登録する。同じ登録要求識別子と同じ内容の再送は同じ成果物へ合流し、異なる内容では置き換えない。登録実績だけでは正式レビューの利用権限を与えない。

正式レビュー設定は信頼済みホストコードから渡し、通常の`.pions.json`には置かない。設定しない場合、正式レビュー用ツールは登録されない。候補プロファイルの設定は本番有効化や段階導入の承認を意味しない。

`pions_review`は、登録済みの成果物識別子と自己完結したレビュー内容だけを受け取り、正式レビューの`Operation`を作成する。結果の完了を待たず、作成済みの`Operation`識別子を直ちに返す。モデル、思考量、ツール、ワーカープロファイル、許可主体、許可時間枠、権限目録、保持方針は、モデルから見えない信頼済み拡張設定に固定する。成果物のダイジェスト、バイト数、形式、正規化規約も入力では受け取らず、Runtimeが登録済み成果物から解決する。

正式レビュー用の信頼済み設定がない場合、`pions_review`は安全側で拒否する。既定のプロジェクト拡張は正式レビュープロファイルを本番有効化していない。設定する候補プロファイルには`formal_reviewer`用途、必須の着手許可、および必須のレビュー対象検証が必要であり、不完全な設定を読み取り用プロファイルへ切り替えない。レビュー対象の現在の利用権限を判定する信頼済み主体も同時に設定する。

`pions_operation`は、現在の信頼済みリポジトリにある`Operation`識別子から、Runtimeが永続化した版付き状態を取得する。応答には状態と失敗理由、着手ゲートと許可期限、起動証跡、実効・観測設定、固定されたレビュー対象、開始配送と開始指示受理、結果受理、停止確認、表示終了処理、および終了処理診断が含まれる。応答へ結果本文は含めない。結果本文は引き続き`pions_result`だけで取得する。別リポジトリの識別子については、存在や保存状態を識別できる情報を返さない。

`pions_review_decision`は、同じPiセッションで`pions_review`が作成した正式レビューについて、確認済みの起動証跡ダイジェストに対する許可または拒否を提出する。モデル向け入力はオペレーション識別子、起動証跡ダイジェスト、判断種別だけであり、コーディネーターの主体と認証情報は信頼済み拡張設定から取得する。設定がない場合や、現在の主体権限、作成時に固定された許可範囲、期限、起動証跡がRuntimeの検査に合格しない場合は安全側で拒否する。判断識別子はPiのセッションとツール呼び出しから拡張が導出し、同じ判断の再送と競合はRuntimeが判定する。

許可後も、Runtimeがレビュー対象を再検証し、開始指示をワーカーが受理するまではレビュー開始済みではない。許可判断と開始指示受理は`pions_operation`で別々に確認する。判断操作は再取得専用Runtimeを使わず、対象を作成した同じPiセッションのRuntimeだけへ提出するため、以前のセッションで作成したオペレーションを許可または再開できない。受理済みの結果は引き続き`pions_result`から取得し、終了処理診断は結果本文へ混入させない。

## セッションとオペレーションの寿命

ツール実行がPiから中断された場合、`pions_delegate`は対応する稼働中`Operation`へ部分木キャンセルを1回要求し、Pionsが停止の証拠を分類するまで待つ。結果待ちをローカルで中断したことや、プロセスへシグナルを送れたことだけではキャンセル成功としない。停止を証明できない場合は`OperationUnknownError`、証明できた場合は`OperationCancelledError`としてオペレーション識別子とともに呼び出し元へ返す。

`pions_review`は結果を待たずにオペレーション識別子を返すが、その正式レビューは同じPiセッション内で終端まで追跡される。非待機だが、セッション終了後も動き続ける機能ではない。

Piセッションの終了、新規作成や再開による切り替え、フォーク、拡張の再読み込みでは、拡張の終了処理が追跡中のすべての稼働中`Operation`へ部分木キャンセルを要求し、すべての分類が終わるまで待つ。中断経路同士が重なっても、同じ`Operation`への要求は1回にまとめる。キャンセル済み、停止を証明できない状態、キャンセル処理の失敗のいずれでも、Pions所有のHerdrペインと永続的な`Operation`記録は削除せず、調査に利用できる状態で保持する。

## モデルによる委譲の選択

ツールの説明と利用指針は、サブエージェントへの委譲や独立したコンテキストでの調査に`pions_delegate`を使い、独立した複数の作業をPiの並列ツール実行で構成するようモデルへ伝える。特定のスキル名や本文を検出する処理は持たない。この説明によってモデルがツールを選ぶことは形式的な保証ではなく、実モデルによる確率的な振る舞いである。Issue #23で実施したモデルによる委譲選択の受け入れ確認は[Issue #23手動スモークテスト](manual-smoke-test-issue-23.md)、Pi CLI可視ワーカーの表示とライフサイクルの受け入れ確認は[Issue #29手動スモークテスト](manual-smoke-test-issue-29.md)に記録する。
