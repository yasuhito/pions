# Pi拡張から作業を委譲する

信頼済みのPionsプロジェクトでは、プロジェクトローカルのPi拡張が`pions_delegate`ツールを登録する。利用前に`npm run build`を実行し、ワーカーラッパーを生成しておく。

`pions_delegate`は、独立したコンテキストへ渡す自己完結した`task`だけを受け取る。モデル、思考レベル、ツール、作業ディレクトリ、状態保存先はツール入力では変更できない。1回の呼び出しは1つのルート`Operation`に対応し、複数の独立した作業はPiの並列ツール実行によって構成する。

初期のワーカーは委譲元セッションのモデルと思考レベルを継承し、`read`、`grep`、`find`、`ls`、`bash`だけを利用する。ワーカーには`bash`を読み取り目的だけに使うよう指示するが、これは技術的な読み取り専用隔離でもセキュリティサンドボックスでもない。ワーカーは信頼済みプロジェクトの`AGENTS.md`を読み込む一方、スキル、拡張、プロンプトテンプレートは読み込まない。

作業内容は所有者だけが読み書きできるファイルで渡す。プロセス引数、オペレーションイベント、ログ、Herdrメタデータには本文を含めない。状態は`XDG_STATE_HOME`が絶対パスならその配下、未指定または相対パスなら`~/.local/state`配下へ保存する。さらに、正規化したリポジトリルートのダイジェストでリポジトリごとに分離する。

Herdr環境がない場合でもツールの登録は維持される。実行すると`HerdrPreconditionError`になり、画面を持たない実行へは切り替えない。ワーカー失敗も自動再試行せず、`Operation`識別子と型付きの理由を含む失敗として呼び出し元へ返す。成功時は永続化済み`Result`の本文を返し、診断情報として`Operation`識別子、バイト数、ダイジェストを付ける。
