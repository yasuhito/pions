# Pi拡張から作業を委譲する

信頼済みのPionsプロジェクトでは、Pi拡張が`pions_delegate`、`pions_result`、`pions_operation`の3つのツールだけを登録する。パッケージの導入手順は[README](../README.md#installation)を参照する。ソースから拡張を利用する開発時は、先に`npm run build`で可視ワーカー用の内部拡張を生成する。特にワーカープロトコル版の変更後にビルドしないと、ホストと内部拡張の版がずれて`Worker configuration version does not match`になるため、同じコマンドで`dist`を更新してから再実行する。

`pions_delegate`は、独立したコンテキストへ渡す自己完結した`task`だけを受け取る。モデル、思考レベル、ツール、作業ディレクトリ、状態保存先はツール入力では変更できない。1回の呼び出しは1つのルート`Operation`に対応し、複数の独立した作業はPiの並列ツール実行によって構成する。

ワーカーは、オペレーションごとに作成する専用Herdrワークスペースの根ペインで、Pi公式の`regular` TUIを持つ一時セッションとして動く汎用サブエージェントである。委譲元のワークスペースやペインは分割せず、フォーカスも移さないため親画面は狭まらない。ワークスペースの表示名は`Pions <短いOperation識別子>`(識別子の先頭8文字)であり、タスク本文を含めない。利用者は必要なときだけHerdr左側のワークスペース一覧から選んで観測する。委譲元セッションのモデルと思考レベルを継承し、`read`、`write`、`edit`、`bash`、`grep`、`find`、`ls`を利用する。`pions_delegate`はワーカーへ提供しないため、委譲は親から一段だけである。ワーカーは親と同じ作業ディレクトリで動き、そこへ直接変更を加える。Pionsはworktreeやブランチを作らず、変更の受け渡しも管理しない。書き込みが競合する委譲を並列実行しない責任は親に置く。失敗した委譲は自動で再実行せず、必要なら親が新しいオペレーションとして明示的に開始する。ワーカーは信頼済みプロジェクトの`AGENTS.md`とPions内部拡張だけを読み込む。`--no-extensions`を維持するため、グローバル拡張やプロジェクト拡張、通常のスキル、プロンプトテンプレート、追加テーマは探索しない。TUIは観測専用であり、端末からの入力はすべて破棄する。

## ワーカーモデルの設定

リポジトリルートの`.pions.json`で、ワーカーのモデルと思考レベルを固定できる。直下の`model`と`thinkingLevel`だけを受け付ける。

```json
{
  "model": {
    "provider": "anthropic",
    "id": "claude-opus-5"
  },
  "thinkingLevel": "high"
}
```

`model`または`thinkingLevel`を省略すると、その値だけを委譲元セッションから継承する。`thinkingLevel`には`off`、`minimal`、`low`、`medium`、`high`、`xhigh`、`max`のいずれかを指定する。モデルはプロバイダーとモデル識別子の正確な組で指定する。以前の`review`階層は未知のキーとして拒否し、互換処理は設けない。

設定には認証情報を記載しない。PionsはPiのモデルレジストリーと既存の認証を使用する。不正なJSON、未知のキー、不正な値は委譲を開始せずに拒否する。指定モデルがモデルレジストリーにない場合、認証されていない場合、またはワーカーで別のモデルが選択された場合も、委譲元モデルへ切り替えず型付き失敗を返す。

Pionsはモデルプロバイダーを同梱せず、委譲元やワーカーへ自動で読み込まない。プロバイダーの導入と認証はPi環境の責任である。ワーカーは拡張を探索しないため、委譲元セッションでPi拡張が登録したプロバイダー(Pi組み込みではないプロバイダー)はワーカーで使えない。そのプロバイダーが設定または継承された場合は、ワーカーを開始する前に`unsupported_capability`の設定エラーを返し、別のプロバイダーへ暗黙に切り替えない。

作業内容とオペレーション権限は所有者だけが読み書きできるファイルで渡す。プロセス引数、オペレーションイベント、ログ、Herdrメタデータには本文を含めない。内部拡張が認証済みの`begin`を受信した後にだけ、作業内容をTUIの通常のユーザーメッセージとして投入する。状態は`XDG_STATE_HOME`が絶対パスならその配下、未指定または相対パスなら`~/.local/state`配下へ保存する。さらに、正規化したリポジトリルートのダイジェストでリポジトリごとに分離する。

Herdr環境がない場合でもツールの登録は維持される。実行すると`HerdrPreconditionError`になり、画面を持たない実行へは切り替えない。ワーカー失敗も自動再試行せず、`Operation`識別子と型付きの理由を含む失敗として呼び出し元へ返す。成功時は永続化済み`Result`の本文を返し、切り詰めの有無にかかわらず本文末尾へ`Operation`識別子を付ける。詳細としても`Operation`識別子、バイト数、ダイジェスト、および終了処理診断の一覧を返す。診断がない場合も一覧は空であり、診断を`Result`本文へ混入させたり成功を失敗へ変更したりしない。結果受理の確認後にPiへ正常終了を要求し、開始トークンを含むプロセス識別情報で停止を確認する。停止を証明できた成功オペレーションでは、永続記録されたPions所有のワークスペースだけを、現在のワークスペース一覧との同一性を照合したうえで自動で閉じる。ワークスペース閉鎖に失敗しても受理済みの結果と終端完了は維持し、表示終了処理の失敗をオペレーションへ記録する。ワークスペース閉鎖と診断保存がともに失敗した場合も、完了応答に残る両方の終了処理診断をツールの詳細へ伝播する。結果受理、Pi終了、または停止を証明できない場合と、失敗の場合は、ワークスペースを調査用に保持する。Pionsが作成・所有していないワークスペースは閉じない。

親のモデルコンテキストへ返す本文は、切り詰め通知を含めてPi標準の2000行または50KB以内に収める。切り詰めた場合も完全な`Result`は永続記録に残り、通知と詳細の`Operation`識別子から参照できる。

`pions_result`は、現在の信頼済みリポジトリに保存された`Operation`の結果を再取得する。入力は`operationId`と、続きがある場合に直前の応答から受け取った`cursor`だけである。結果の保存場所や分割サイズは指定できない。各断片は結果全体の完全性検証後に返され、結果受理識別子、受理した原文バイト列のSHA-256ダイジェスト、および次の断片用カーソルまたは完了表示を含む。結果受理識別子は`pions_operation`が返す結果受理と同じ値であり、外部の正規化済み文書のダイジェストとは区別する。Piセッションを再起動した後も、同じリポジトリの状態保存先を開いて取得できる。別リポジトリの識別子に対しては、保存場所、存在、削除、破損などを識別できる情報を返さない。

## セッションとオペレーションの寿命

ツール実行がPiから中断された場合、`pions_delegate`は対応する稼働中`Operation`へキャンセルを1回要求し、Pionsが停止の証拠を分類するまで待つ。結果待ちをローカルで中断したことや、プロセスへシグナルを送れたことだけではキャンセル成功としない。停止を証明できない場合は`OperationUnknownError`、証明できた場合は`OperationCancelledError`としてオペレーション識別子とともに呼び出し元へ返す。

Piセッションの終了、新規作成や再開による切り替え、フォーク、拡張の再読み込みでは、拡張の終了処理が追跡中のすべての稼働中`Operation`へキャンセルを要求し、すべての分類が終わるまで待つ。中断経路同士が重なっても、同じ`Operation`への要求は1回にまとめる。ワーカー停止を証明できたキャンセル済みの場合は、成功時と同じ同一性照合を経てPions所有のワークスペースを閉じる。停止を証明できない状態やキャンセル処理の失敗では、Pions所有のHerdrワークスペースを調査に利用できる状態で保持する。いずれの場合も永続的な`Operation`記録は削除しない。

## モデルによる委譲の選択

ツールの説明と利用指針は、サブエージェントへの委譲や独立したコンテキストでの調査に`pions_delegate`を使い、独立した複数の作業をPiの並列ツール実行で構成するようモデルへ伝える。特定のスキル名や本文を検出する処理は持たない。この説明によってモデルがツールを選ぶことは形式的な保証ではなく、実モデルによる確率的な振る舞いである。Issue #23で実施したモデルによる委譲選択の受け入れ確認は[Issue #23手動スモークテスト](manual-smoke-test-issue-23.md)、Pi CLI可視ワーカーの表示とライフサイクルの受け入れ確認は[Issue #29手動スモークテスト](manual-smoke-test-issue-29.md)に記録する。
