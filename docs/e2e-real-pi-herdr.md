# 実PiとHerdrによるE2E検証

Issue #106で追加した`scripts/e2e-real-pi-herdr.mjs`は、本物のPiとHerdrを使って委譲・結果受理・結果再取得・ワーカーワークスペースの終了を自動検証する。手動の[`verify-pions`スキル](../.cursor/skills/verify-pions/SKILL.md)が人手で行う検証を、隔離された使い捨てのHerdrセッションの中でスクリプト化したものであり、既存のHerdrセッション、ワークスペース、および利用者のPi設定を変更しない。

## 実行方法

```bash
npm run test:e2e
```

単一のこのコマンドだけで、ビルド、隔離環境の準備、検証、後始末までを行う。CI(`npm run check`)には含めない。実際のモデル呼び出しを伴うため、実行のたびに料金と数十秒程度の時間がかかる。

## 必要条件

- Node.js 26以上(CIと同じ)
- `herdr`がPATH上にあること(検証時点の動作確認は0.9.0)
- `pi`がPATH上にあること(検証時点の動作確認は0.85.1)
- `~/.pi/agent/auth.json`にPiのLLM認証情報があること
- `.pions.json`の`model`が指すプロバイダー・モデルが認証済みであること(`pi auth check --provider <provider> --model <id>`で確認できる)

いずれかが満たされない場合、スクリプトは検証を始める前に理由を示して失敗する。

## 何を検証するか

1. **既知のUTF-8最終回答**: 親のPiセッションに`pions_delegate`を1回だけ使うタスクを渡す。タスクは絵文字と日本語を含むランダムな既知文字列を`bash`の`printf`で出力させ、同じ文字列を`write`で作業ディレクトリ直下の使い捨てファイルへ書き、その文字列だけを最終回答として返す自己完結した内容である。ワーカーの最終回答がその文字列とバイト単位で一致することを確認する。
2. **実効ツール面**: 観測用の検証拡張から親Piの有効ツールを取得し、Pions由来のツールが3つだけであることを確認する。完了したオペレーションから、ワーカーの実効ツールが7つだけであり、`pions_delegate`を含まないことも確認する。
3. **入れ子の共有作業ディレクトリへの書き込み**: 親をリポジトリ内の使い捨て入れ子ディレクトリから起動する。1でワーカーが相対パスに書いたファイルがその入れ子ディレクトリに存在し、内容が既知文字列と一致すること、およびオペレーションの実効`cwd`が同じ正規化済みパスであることを確認する。ファイルとディレクトリは成功・失敗にかかわらず削除する。
4. **ワーカーワークスペースのライフサイクル**: 1の委譲中に`herdr workspace list`を定期的に観測し、新しく現れたワークスペースがちょうど1つで、表示名が`Pions <Operation識別子の先頭8文字>`であり、フォーカスを持たず、委譲元ワークスペースがフォーカスを保ったままであることを確認する。委譲成功後にそのワークスペースが一覧から消えていること、および6で取得する`Operation`の表示終了処理証跡が同じワークスペース識別子の完了記録で、終了処理診断が空であることも確認する。
5. **別のPiセッションからの結果再取得**: 1で得た`Operation`識別子を使い、まったく別のPiプロセス(`--no-session`の新規セッション)から`pions_result`で同じ結果を取得し、本文とSHA-256ダイジェストが1と一致することを確認する。
6. **開始前の設定拒否**: `.pions.json`を一時的に旧`review`形式へ差し替えた場合と、検証用Pi拡張だけが登録したプロバイダーを指定した場合に、`pions_delegate`がエラーとなりワーカーワークスペースを作らないことを確認する。失敗した呼び出しが1回だけで自動再実行されないことも確認し、元の設定は必ず復元する。

親のPiは`--mode json --no-extensions --extension <このリポジトリのpions拡張> --approve --no-session -p @<promptファイル>`として起動する。`--no-extensions`と明示的な`--extension`は、利用者が別チェックアウトの`pions`拡張をグローバルに登録している場合の「同名ツールが競合してロードに失敗する」事故を避けるためであり、どの開発機でも常にこのリポジトリのビルド済み拡張だけを読み込む。`--approve`は今回の実行だけプロジェクトローカルファイル(`AGENTS.md`や`.pions.json`)を信頼し、共有の`~/.pi/agent/trust.json`を書き換えない。委譲されたワーカー自身は、既存の可視ワーカー実装がそのまま専用のHerdrワークスペースへ通常どおり起動する。ワーカーは`--no-extensions`で動き、Pionsはプロバイダー拡張を同梱も読み込みもしないため、`.pions.json`の`model`にはPi組み込みのプロバイダーを指定する。

## 隔離の仕組み

- Herdrセッションは`pions-e2e-<pid>-<random>`という名前で毎回新規生成し、`default`セッションには一切触れない。セッション用のHerdrサーバーもこの名前専用に起動し、実行後に`session stop`・`session delete`で確実に終了させる。
- Herdrのライフサイクルを自分で管理する監督側は、起動済みの`default`以外のセッション名を`PIONS_E2E_HERDR_SESSION`で、そのセッションへ全呼び出しを限定するラッパー実行ファイルを`PIONS_E2E_HERDR_COMMAND`で渡せる。この場合スクリプトはHerdrサーバーの起動とセッションの停止・削除を行わず、供給されたセッション内で自分のワークスペースを作成・終了するだけになる。`PIONS_E2E_HERDR_COMMAND`は`PIONS_E2E_HERDR_SESSION`と同時に指定する。
- 委譲元と結果取得用のワークスペースはそれぞれ新規作成する。委譲元の`cwd`はリポジトリ内の使い捨て入れ子ディレクトリ、他の検証用ワークスペースはリポジトリルートを使う。`XDG_STATE_HOME`は実行ごとに作る一時ディレクトリへ`--env`で上書きするため、`Operation`の永続状態は利用者の`~/.local/state/pions/`ではなく使い捨ての一時ディレクトリへ保存され、他の検証や日常利用のPions状態と混ざらない。

## 成功時と失敗時の後始末

成功・失敗のいずれでも、作成したワークスペースを閉じ、自分で生成した隔離セッションなら`session stop`・`session delete`を実行する。加えて:

- **成功時**: 一時ディレクトリ(プロンプト、Piの`--mode json`出力、標準エラー、Herdrサーバーログ)を削除する。
- **失敗時**: 一時ディレクトリ全体と、失敗時点の`herdr pane list`・`herdr workspace list`出力を`PIONS_E2E_EVIDENCE_DIR`(未指定なら`/tmp/pions-e2e-evidence-<タイムスタンプ>`)へコピーしてから、Herdr資源だけを後始末する。診断が必要な場合はこのディレクトリを調査する。標準エラーには保存先のパスを出力する。

## 既知の制約

- ローカル開発機での実行を前提とし、`herdr --remote`によるリモートセッションは対象外。
- 実際のLLM呼び出しを伴うため、モデル側の応答が指示に従わない場合はまれに失敗しうる(その場合も診断は保存される)。
