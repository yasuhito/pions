## Method and evidence rules

This is static primary-source research. I inspected package manifests and TypeScript/JavaScript, Markdown, and configuration files; I did **not** install or execute any package. “Source facts” below describe the cited implementation. “Recommendations” are confined to the final section.

For reproducibility, the review revision is the npm release's `gitHead` where npm supplied one, otherwise the exact version tag, and otherwise the repository HEAD observed on 2026-09-05. Every source link is commit-pinned and its URL contains the full hash. The Pi index is the authority for which cards and versions were listed; the repositories/manifests are the authority for implementation claims.

## Source-fact synthesis by requested dimension

### Package shape and entry points

The implementations divide into four materially different shapes:

1. **True Pi child runtimes:** `pi-herdr-agents`, both `pi-herdr-subagents` variants, `@minhduydev/pi-subagents`, `@yofriadi/pi-subagent-herdr`, `pi-pier`, Shepherd/Shepherdr, `@tian.zuo/pi-subagents`, `pi-herdr-live-agents`, and the planning bundle. They register parent tools and usually a restricted child-side completion/reporter tool.
2. **Herdr control substrates:** `@ogulcancelik/pi-herdr`, `@sfroment/pi-herdr`, `@andrewjacop/pi-herdr`, `@henryqw/pi-herdr`, and `pi-terminal-mux`. These manage surfaces/processes but do not by themselves establish durable parent/child semantics.
3. **Workflow/crew layers:** `ry-skill`, `@itc-steve/pi-herdr`, `mu`, `pi-herdr-squad`, `@ret2hell/pi-herdr-orchestrator`, Apnea, Agent Fleet, and the planning bundle. These add stages, DAGs, roles, reviews, or setup policy.
4. **Adjacent utilities:** title/status/fork/worktree/todo/terminal/peer/notification packages. They are useful components or UX precedents but are not subagent harnesses.

### Lifecycle and Herdr integration

Three completion authorities appear in source:

- **Explicit child artifact/tool:** qcts, live-agents, Shepherd, squad, Tian, and Pier. This gives a typed terminal outcome and is safest for nesting.
- **Pi session/event boundary:** qcts waits for `agent_settled`; the subagent family records activity from Pi events; Pier replays session custom entries. This avoids treating an intermediate `agent_end` as final.
- **Herdr state/terminal observation:** generic Herdr tools and older orchestrators wait on native agent state, terminal stability, output markers, or ledger text. This is useful for liveness but is weaker as the sole semantic completion signal.

All serious integrations use Herdr IDs rather than focus-dependent keystrokes. The safer ones distinguish surfaces they created from caller-owned surfaces and retain evidence when termination cannot be proven.

### Model and thinking configuration

The recurring precedence is **explicit invocation → role/profile → package/global config → parent runtime**. `pi-herdr-agents`, legacy `pi-herdr-subagents`, qcts, squad, and live-agents validate exact Pi model IDs and supported thinking levels. `@itc-steve/pi-herdr` instead partitions a default local model and ranked “think” models. Shepherd makes the role authoritative; Tian makes profiles authoritative. `mu` deliberately does not choose model/thinking and delegates launch commands to environment configuration.

Silent fallback is generally dangerous: the better packages reject unavailable pinned models or report which fallback was selected. The qcts implementation also records observed runtime details in completion evidence.

### Nesting

Only three reviewed designs provide substantial positive input for arbitrary nesting:

- **qcts:** explicit parent/descendant ownership, continuation batching, completion delayed until descendants settle, cancellation acknowledgement after descendant drain, and direct self-type recursion rejection.
- **MinhDuy:** recursive handle/scope API and descendant-first stop with bounded settlement reporting.
- **pi-herdr-agents / legacy pi-herdr-subagents:** child tools can remain enabled, with role-level `spawning: false`/deny controls; this is flexible but less structurally strict.

Several packages intentionally prohibit nesting (`@yofriadi/pi-subagent-herdr`, live-agents, Pier's default worker, squad), and others merely make accidental recursion possible because installed extensions load in a child (`@andrewjacop/pi-herdr`). Accidental availability is not a nesting protocol.

### Persistence and history

- **Strong durable control state:** MinhDuy's run/task stores and `mu`'s SQLite/WAL DAG.
- **Session-event sourcing:** Pier and todo-herdr use Pi session entries, which naturally follow session branch/reload semantics.
- **Durable append logs:** ry-skill pipelines, ITC journals, workflow journals, and peer mailboxes.
- **Ephemeral operation artifacts:** qcts intentionally disables child Pi session persistence and does not recover old outcomes in a new parent process.
- **Human-readable child history:** pi-herdr-agents and live-agents keep real Pi session/pane history; live-agents explicitly retains panes.

### Failure, cancellation, and security

The strongest failure patterns are: rollback only newly created surfaces; preserve caller-owned or evidence-bearing surfaces; distinguish turn interrupt from process cancellation; report “unknown” when process death cannot be proved; make terminal outcome single-writer/at-most-once; and cancel descendants before acknowledging parent cancellation.

Common security limitations are also explicit in first-party sources:

- A Herdr pane, Git worktree, VM, or Worker thread is **not** an OS security sandbox.
- Read-only role claims are not enforceable if arbitrary Bash remains available.
- Generic Herdr wrappers expose destructive process/session operations.
- Task text in argv can be visible in process listings; prompt files/mailboxes reduce that exposure.
- Peer and child output is untrusted model input and needs size bounds and delimiter/framing defenses.
- Remote SSH helpers, custom CLI templates, `--yolo`, `--dangerously-skip-permissions`, and `sudo sh -c` are deliberate high-trust boundaries, not implementation conveniences.

## Recommendations for the Python harness (not source facts)

1. **Use a small two-sided protocol.** Run a Python supervisor in the parent and a minimal child reporter plugin/helper in every spawned pane. Give each operation a random ID and capability token. The reporter emits typed `started`, `activity`, `blocked`, `completed`, `failed`, and `cancelled` records; terminal output is observability only.
2. **Make lineage first-class.** Persist `operation_id`, `parent_operation_id`, `root_operation_id`, depth, child IDs, Herdr workspace/tab/pane IDs, Pi session reference, model/thinking, cwd/worktree, state sequence, and cancellation epoch. Enforce maximum depth, fan-out, total live descendants, and budget. Reject direct same-profile recursion unless explicitly permitted.
3. **Adopt qcts-style settlement.** A node may be self-settled while descendants still run. Publish parent completion only after its direct descendants and pending result handoffs drain. On cancellation: atomically freeze new children, propagate descendant-first, wait to a deadline, record failures/unknowns, then acknowledge upstream.
4. **Add stronger crash recovery than qcts.** Use SQLite in WAL mode (or rigorously locked append-only JSONL) under a mode-`0700` harness directory with mode-`0600` artifacts. Reconcile records against Herdr native agent identity at startup. Never “adopt latest session”; require exact operation, pane, and child-session identity.
5. **Use `asyncio.create_subprocess_exec`, never a shell.** Pass Herdr as an argv array; validate IDs/enums; bound stdout/stderr/timeouts. Put task prompts in private files or a local authenticated socket rather than command-line arguments. Do not offer a generic “any Herdr subcommand” model tool.
6. **Separate liveness from semantic completion.** Subscribe to Herdr events or poll native `agent get` for process/liveness; accept semantic results only through the authenticated child channel. Treat `agent_end` as intermediate and `agent_settled` plus descendant drain as terminal.
7. **Snapshot runtime policy at spawn.** Resolve exact provider/model ID and thinking level once, validate them, record them with the operation, and pass them explicitly. Do not silently change model or widen tools on resume/recovery.
8. **Keep panes visible and ownership-safe.** Default to background tabs/panes without focus theft, retain failed/blocked panes for inspection, and close only surfaces recorded as supervisor-owned. Offer separate `interrupt turn`, `cancel subtree`, `close surface`, and `forget history` actions.
9. **Treat worktrees as consistency tools, not sandboxes.** Use exclusive writable scopes or one worktree per writing subtree, but combine that with child tool allowlists and OS-level controls if hostile code is in scope. Never claim Bash is read-only.
10. **Bound all model-to-model data.** Size-limit tasks/results/history; frame and escape untrusted child/peer text; redact secrets before persistence; store hashes and pointers for oversized results. Deliver each terminal result at most once, but keep an auditable durable record for replay.

A pragmatic implementation order is: **(1)** live-agents-style visible pane + capability mailbox, **(2)** qcts-style lineage/descendant settlement/cancellation, **(3)** Pier-style event-sourced recovery, then **(4)** optional MinhDuy/mu-style durable scheduling, claims, reviews, and worktrees. This keeps the initial Python module deep and testable rather than reproducing an entire workflow platform.
