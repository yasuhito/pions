    deadloopの推奨経路
    
    
    
  
    

  
    
    
    このチケットで決めたい案
    
    
      
      
    1. deadloopとQoralは、それぞれが所有する信頼済みブートストラップのパッケージマニフェストで"@yasuhito/pions": "0.1.0"を直接依存として宣言する。
      2. 
      
    2. 入口はESMとして@yasuhito/pions/formal-reviewだけを読み込む。cwdに関係なく、入口ファイルを起点とするNode標準解決へ任せる。探索用のcreateRequire、NODE_PATH、グローバルnpmルート走査、利用先設定の絶対パスは使わない。
      3. 
      
    3. 実行時は公開されたmoduleIdと契約版1を照合し、不一致・検査不能を拒否する。解決先パスは診断にだけ使う。
      4. 
      
    4. 正規配布物かどうかは実行時の自己申告ではなく、導入時の正確な版、lockfileまたはshrinkwrapの完全性、署名・来歴で検査する。
      5. 
      
    5. deadloopは専用ESM入口をグローバルdeadloopパッケージ内に置く。Qoralは専用NodeパッケージをQoral配布物に置き、Rustが実行ファイル相対でその入口を短命起動する。
      6. 
    
    
    
    人間に決めてほしい点: deadloopの現行pi install git:は凍結インストールではない。正式レビュー入口を有効にする導入経路を、(A) npm公開したdeadloop + npm shrinkwrap、または (B) 別の管理者所有インストーラーによるnpm ciに限定する案でよいか。通常のgit導入は読み取り用途だけに残す。
